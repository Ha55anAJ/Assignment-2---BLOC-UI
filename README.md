# Campus Lost & Found

A Flutter app for posting, finding and claiming lost items around IBA,
backed by **Cloud Firestore** and built with Clean Architecture and
`flutter_bloc`, for the IBA course *Application Development for Mobile
Devices (CSE-450)*, Assignment 3.

## Features

- **Real-time list.** The home screen streams the `items` collection with
  `.snapshots()`. Adding, editing or deleting a document anywhere (another
  phone, the Firebase console) updates the list without a refresh.
- **Search and filter together.** Search by title and pick a status chip
  (All / Lost / Found / Claimed). Both apply at the same time, and each chip
  shows how many results it would give for the current search.
- **Post an item.** A validated form writes a new document to Firestore.
- **Race-safe "Mark as Claimed".** Claiming runs in a Firestore transaction,
  so two people tapping it at the same moment can never claim an item twice.
- **Delete.** Swipe a card away or use the delete button on the detail
  screen, with a confirmation dialog.
- **Live detail screen.** Shows the full description and follows the item's
  document, so its status badge and a "Returned to its owner" banner update
  as soon as someone claims it elsewhere.
- **One-time seed.** The first launch writes the 8 sample items from the
  brief.

## Firestore data model

Collection `items`, one document per item:

| Field         | Type      | Notes                                   |
| ------------- | --------- | --------------------------------------- |
| `title`       | string    | e.g. "Black Backpack"                   |
| `category`    | string    | Bag, Accessory, ID Card, Electronics, … |
| `location`    | string    | Where it was lost or found              |
| `status`      | string    | `Lost`, `Found` or `Claimed`            |
| `description` | string    | Shown in full on the detail screen      |
| `postedBy`    | string    | Name of the person who posted it        |
| `createdAt`   | timestamp | Server timestamp when posted            |
| `claimedAt`   | timestamp | Set once, by the claim transaction      |

`meta/seed` records that the sample items were written, so deleting them
later does not bring them back.

## How "Mark as Claimed" stays consistent

`ItemRemoteDataSource.claimItem` runs `FirebaseFirestore.runTransaction`:

1. read the item inside the transaction;
2. if it is missing, report *not found*; if it is already `Claimed`, report
   *already claimed* and write nothing;
3. otherwise update `status` to `Claimed` and set `claimedAt`.

If another device changes the document between the read and the write,
Firestore discards the attempt and re-runs the handler with fresh data, so
only one of two simultaneous taps succeeds. The other gets "Someone has
already marked this item as claimed". On the device itself, the claim button
is disabled while the request runs, and the bloc drops repeated taps
(`droppable()` from `bloc_concurrency`). `firestore.rules` also allows only
Lost/Found → Claimed, so an item cannot be un-claimed.

## Structure

```
lib/
  main.dart                    Firebase.initializeApp, wiring, one-time seed
  app.dart                     MaterialApp, RepositoryProvider, ItemsBloc
  firebase_options.dart        Generated by `flutterfire configure`
  core/theme/                  Colors, fonts and ThemeData
  features/items/
    domain/                    Pure Dart: no Flutter or Firebase
      entities/item.dart       Item, ItemDraft, ItemStatus
      failures/failure.dart
      repositories/item_repository.dart
      usecases/                WatchItems, WatchItem, AddItem, ClaimItem,
                               DeleteItem, SeedItems
    data/
      models/item_model.dart                    Item <-> Firestore document
      datasources/item_remote_data_source.dart  Streams, transaction, seed
      datasources/seed_items.dart               The 8 sample items
      repositories/item_repository_impl.dart    Errors -> Failures
    presentation/
      bloc/items/              Live list, search, status filter, delete
      bloc/item_detail/        Live item, claim, delete
      bloc/add_item/           Saving the form
      pages/                   List, detail and "Post an item" screens
      widgets/                 Card, status badge, filter chips, …
firestore.rules                Security rules for items and meta/seed
```

Dependencies point inward: presentation and data depend on domain, and domain
depends on nothing.

## Setup

The app is connected to the Firebase project `app-dev-exam`. To point it at
another project:

```bash
dart pub global activate flutterfire_cli
flutterfire configure --project=<your-project-id> --platforms=android,ios,web
firebase deploy --only firestore:rules --project <your-project-id>
```

Cloud Firestore must be enabled in the Firebase console for that project.

## Run

```bash
flutter pub get
flutter run
```

## Test

```bash
flutter analyze
flutter test
```

The tests use `fake_cloud_firestore`, so they need no network or Firebase
project. `test/widget_test.dart` runs the whole app (screens, blocs,
repository and data source) against the fake database.
